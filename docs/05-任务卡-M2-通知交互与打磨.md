## M2-1 WinRT Toast 交互通知（最高风险卡，最先做）

**前置**：M1 完成
**目标**：替换 M1-4 的过渡通知，实现带按钮的 Windows 原生 Toast。

### 给 agent 的任务描述（直接粘贴）

```
用 WinRT 自实现 TodoEdge 的交互式 Toast 通知。先读：
- D:\ztodo\docs\01-产品方案框架-v1.md 第 4.2 节（Toast 结构与行为规格）
- D:\ztodo\docs\02-开发总指南.md 第 8 节风险第 1 条、第 4.3 节

背景（重要）：tauri-plugin-notification 不支持按钮，本卡整体替换为 windows-rs
直接调 WinRT ToastNotification，参考思路：Toast XML 自定义按钮 +
ToastNotificationManager 的 activated/dismissed 事件监听。

实现：
1. src-tauri/src/toast.rs（#[cfg(windows)] 门控，符合 AGENTS.md 平台纪律）：
   - show_toast(task) 组装 Toast XML：
     标题「待办提醒」，正文=任务标题（过期任务附「已过期 X 分钟」）
     按钮1 action="完成" → 携带 task_id
     按钮2 action="稍后提醒" → 携带 task_id
   - 监听 Toast 激活事件，区分三种来源路由：
     a) 点按钮「完成」→ 调 toggle 完成 + emit 事件刷新前端（面板不弹出）
     b) 点按钮「稍后提醒」→ remind_at += 10 分钟（读 settings 可配）、notified=0，
        重新进入调度
     c) 点通知主体 → emit "open_panel_and_highlight" 事件，前端呼出面板并高亮该任务
   - 通知声音用系统默认
2. scheduler.rs 改调 toast.rs 的 show_toast，卸载 tauri-plugin-notification。
3. ⚠ 关键机制确认：WinRT 事件回调在应用进程内才有效。同时处理「应用在跑但主窗口
   收起」的正常场景；应用完全退出后通知自然不弹（已接受，见 01 文档第 11 节）。
4. 前端监听对应事件：任务完成刷新列表；open_panel_and_highlight 时 expand + 滚动
   到该任务 + 高亮描边 2 秒。
5. 自测三条路径（完成按钮/稍后按钮/点主体）。
6. cargo check + tsc 通过后提交："M2-1: WinRT 交互通知"。
```

### 验收（你来操作）

- [ ] 到点通知带两个按钮：「完成」「稍后提醒」
- [ ] 点「完成」：任务变已完成（展开面板可见），面板没有弹出
- [ ] 点「稍后提醒」：10 分钟后通知再次弹出（可临时把间隔调短验证）
- [ ] 点通知本体：贴边面板弹出，对应任务高亮
- [ ] 通知有系统提示音

### 已知坑（止损预案）

- WinRT 事件监听与 Tauri 事件循环的线程交互是难点。若 agent 3 轮内搞不定按钮回调：先让它实现「点通知主体呼出面板」（这条链路简单），按钮方案去问网页模型要第二意见（02 指南 7.4 升级路径），再不行回滚本卡，M2 其余卡不受阻塞（它们不依赖通知按钮）。

## M2-3 中文自然语言时间输入

**前置**：M1 完成（不依赖 M2-1）
**目标**：输入框敲「明天9点开会」自动解析提醒时间。

### 给 agent 的任务描述（直接粘贴）

```
实现中文自然语言时间解析与时间设置 UI。先读：
- D:\ztodo\docs\01-产品方案框架-v1.md 第 4.3 节（解析范围与预览规则）

实现：
1. src/lib/parseTime.ts（纯前端 TS，dayjs 辅助）：
   规则白名单（不引入 NLP 库，白名单外一律解析失败）：
   - 相对日：今天 / 明天 / 后天 / 大后天
   - 星期：周一~周日、星期一~星期日（解释为未来最近的那天，今天则下周）
   - 时段+钟点：上午/早上/中午/下午/晚上 + N点/N点半/N:MM（无时段的 N点 按
     上午<12 用上午、≥12 按下午解释；「3点」=15:00）
   - 相对时长：N分钟后 / N小时后 / N天后
   - 完整时间：HH:MM、M月d日、M月d日+HH:MM（年份取今年，已过则明年）
   解析返回 { time: Dayjs, matchedText: string } | null
2. 输入框交互：
   - 输入时实时解析，输入框下方（或框内右端）显示预览「将提醒：明天 09:00」
   - 回车/＋ 添加：剥离 matchedText 后剩余文字作为标题；解析失败整句作标题、无提醒
   - 预览明确可辨（比如小字灰色），失败时不显示预览
3. ⏰ 按钮（M1-5 占位）实现：点击弹 Win11 风格 DateTimePicker 弹层（日期+时间，
   可选「清除提醒」），确认后写入当前输入任务的提醒时间（用于事后改期）。
   任务行的时间文字点击也可打开同一弹层（改期入口）。
4. 自测：覆盖白名单每类规则 + 失败回退。
5. tsc 通过后提交："M2-3: 自然语言时间"。
```

### 验收（你来操作）

- [ ] 输入「明天9点开会」出现预览「将提醒：明天 09:00」，回车后任务标题是「开会」、时间设为明天 9 点
- [ ] 输入「30分钟后喝水」正确解析
- [ ] 输入「买个灯泡」无预览，作为纯标题任务
- [ ] 点任务行时间文字能弹选择器改期/清除
- [ ] 解析结果和预览不一致时以选择器修正为准
