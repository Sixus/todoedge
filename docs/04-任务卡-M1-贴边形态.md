### 操作步骤

1. 打开 [v0.dev](https://v0.dev)，登录，新建设计。
2. 把下面的提示词贴进去（可在其基础上用自己的话追加要求）：

```
设计一个 Windows 11 Fluent 风格的桌面待办应用侧边面板，深色主题、
半透明背景（将运行在 Mica 云母材质上，所以背景要设计成半透明深色，

面板固定宽 340px、高约屏幕 70%，从上到下四段：
```

## M1-2 贴边窗口形态（核心卡）

**前置**：M1-1
**目标**：细条常驻右缘 + 悬停延时呼出 + 离开自动收 + 不抢焦点 + 全屏隐藏。

### 给 agent 的任务描述（直接粘贴）

```
实现 TodoEdge 的贴边窗口形态。先读：
- D:\ztodo\docs\01-产品方案框架-v1.md 第 3 节（窗口形态与交互规格、状态机）
- D:\ztodo\docs\02-开发总指南.md 第 4.1 节（单窗口动态尺寸架构——严格按此实现）

实现要求：
1. src-tauri/src/window_ctl.rs：
   - expand_panel / collapse_panel 两个 #[tauri::command]
   - 收起态：窗口 6px 宽 × 主屏高度 40%，贴主屏右缘垂直居中
   - 展开态：窗口 340px 宽 × 主屏高度 70%，贴主屏右缘垂直居中
   - 用 primary_monitor() 拿主屏尺寸计算位置；DPI 缩放用 Tauri 的 LogicalSize/Position 处理
   - Win32 设置（通过 window.hwnd()，windows crate）：扩展样式加
     WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE，确保不进任务栏/Alt+Tab 且显示时不抢焦点；
     Tauri 的 focused(false) 有已知 bug（tauri#7519），以 Win32 样式为准
   - 全屏检测：tokio 任务每 2s 调 SHQueryUserNotificationState，
     检测到全屏时 hide()，退出全屏恢复 show()（仅收起态；全屏中不响应呼出）
2. tauri.conf.json：主窗口改为 decorations:false、shadow:false、resizable:false、
   skip_taskbar:true、transparent:true（transparent 本卡先配上，M1-3 才真正用）、
   初始即收起态尺寸
3. 前端 src/components/Strip.tsx（细条视图）：
   - 视觉：宽 6px、高 100%（窗口高度），半透明白色圆角条，hover 时透明度提高
     （气质参考 iOS Home Indicator 小白条，竖向）
   - mouseenter 后 400ms 仍悬停 → invoke expand_panel → 切换到 Panel 视图
4. 前端 Panel.tsx（面板视图）：
   - mouseleave 启动 1500ms 倒计时收起（倒计时内鼠标回到面板则取消）
   - 焦点在输入框内（编辑态）时不自动收，改为「点击面板外任意处」才收
     （点击外部检测：全局点击监听 + 面板失焦）
   - Esc 键收起
5. App.tsx 维护 collapsed 状态切换两个视图；窗口几何由 Rust 管，前端只管视图切换，
   两者通过 expand/collapse 命令的返回或事件同步，防止状态漂移
6. 自测：细条常驻→悬停出面板→移开 1.5s 收回→编辑时不自动收
7. cargo check + tsc 无错误后提交："M1-2: 贴边窗口形态"。
```

### 验收（你来操作）

- [ ] 启动应用：右缘中有一条竖向半透明细条（约 6px 宽），任务栏没有 TodoEdge 图标
- [ ] 鼠标放到细条上约半秒，面板从右缘滑出（340px 宽）
- [ ] 鼠标移开面板约 1.5 秒，自动收回细条
- [ ] 在输入框打字时把鼠标移走，面板**不**消失；点一下面板外才收
- [ ] **不抢焦点**：面板展开时，点击另一个程序窗口（如浏览器），该窗口正常获得焦点；再悬停细条，面板出现且当前焦点不被抢走
- [ ] 全屏播放视频/游戏时细条消失，退出全屏后细条回来
- [ ] Win+D 显示桌面后细条仍在（细条 always_on_top 或属于不受影响的层级，如异常请反馈 agent）

### 已知坑

- 多显示器：只锚定主屏（`primary_monitor`），副屏什么都不显示。
- 「点击面板外收起」在 WS_EX_NOACTIVATE 下窗口可能收不到失焦事件——agent 需用全局鼠标钩子或 `GetCursorPos` 轮询兜底（02 指南 4.1 已提）。
- 展开动画如果窗口 resize 卡顿，可以先用无动画版本，动画放 M2-5 打磨。

## M1-3 Mica 云母外观

**前置**：M1-2
**目标**：面板呈 Win11 Mica 半透明质感，深浅色跟随系统。

### 给 agent 的任务描述（直接粘贴）

```
为 TodoEdge 启用 Mica。先读：
- D:\ztodo\docs\01-产品方案框架-v1.md 第 7 节（外观系统）
- docs\design\panel-dark.png / panel-light.png（M1-1 的视觉基准）

实现：
1. 依赖加 window-vibrancy（Tauri 2 兼容版本）。
2. setup 钩子里对主窗口 apply_mica()（dark 参数跟随系统主题；Win11 22621+ 判定，
   不满足时 fallback apply_acrylic，再不满足什么都不做走实体背景）。
3. CSS：html/body 背景透明；面板容器用半透明深色（如 rgba(32,32,32,0.75)），
   深浅两套 CSS 变量（theme.css），跟随 prefers-color-scheme 切换。
4. 收起态细条同样透明背景上的半透明白色。
5. 自测深浅两种系统主题下的观感，与 design 截图对照大致一致即可（细节打磨在 M1-5）。
6. cargo check + tsc 通过后提交："M1-3: Mica 外观"。
```

### 验收（你来操作）

- [ ] 面板背景呈半透明云母质感（能隐约透出桌面壁纸，但内容清晰可读）
- [ ] Windows 设置切换深色/浅色模式，面板配色跟着变
- [ ] 细条在浅色壁纸和深色壁纸上都看得见

### 已知坑

- Mica 只在 Win11 22621+；Win10 会走 acrylic 或纯色 fallback——验收以你的 Win11 为准。
- 拖动窗口卡顿与 blur 模式相关，我们不用 blur，若仍卡顿反馈给 agent 排查。

## M1-4 基础提醒（过渡版通知）

**前置**：M1-2（M1-3 可并行）
**目标**：到点弹 Windows 通知（本卡无按钮，M2-1 才做「完成/稍后提醒」按钮）。

### 给 agent 的任务描述（直接粘贴）

```
实现提醒调度与基础通知。先读：
- D:\ztodo\docs\01-产品方案框架-v1.md 第 4 节（提醒系统规格）
- D:\ztodo\docs\02-开发总指南.md 第 4.3 节（调度器设计）

实现：
1. src-tauri/src/scheduler.rs：tokio 任务每 30s 查询
   done=0 AND notified=0 AND remind_at <= now 的任务，逐条发通知并置 notified=1。
   应用启动时立即跑一次（处理关机期间错过的提醒——过期不重弹原则：错过的也弹一次，
   因为通知本来就没弹过）。
2. 通知用 tauri-plugin-notification（过渡方案，M2-1 会整体替换为 WinRT 自写版）：
   标题「待办提醒」，正文=任务标题。本卡不需要按钮和点击回调。
3. 任务数据链路：add_task 的 remind_at 参数打通（M0-3 已有字段；前端输入框暂无
   设时间 UI，先用已有 update_task 命令在 Rust 侧加一个测试用命令或临时按钮设时间，
   M2-3 换成正式的自然语言+点选器）。
4. 自测：建任务设 1 分钟后提醒，等通知弹出。
5. cargo check + tsc 通过后提交："M1-4: 基础提醒"。
```

### 验收（你来操作）

- [ ] 建一条任务并设 2 分钟后的提醒（按 agent 提供的临时方式），到点系统右下角弹通知
- [ ] 通知只弹一次，不重复
- [ ] 勾选完成的任务不再弹提醒
