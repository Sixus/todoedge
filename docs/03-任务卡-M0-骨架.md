## M0-3 数据层

**前置**：M0-2
**目标**：SQLite 落盘 + 全套 invoke 命令，数据层可独立编译验证。

### 给 agent 的任务描述（直接粘贴）

```
实现 TodoEdge 数据层。先读：
- D:\ztodo\docs\01-产品方案框架-v1.md 第 6 节（表结构，含 group_id 预留字段）
- D:\ztodo\docs\02-开发总指南.md 第 4.2 节（数据流）、第 3 节（用 rusqlite，不用 sqlx）

要求：
1. src-tauri/migrations/001_init.sql：建 tasks 与 settings 两表（字段严格按 01 文档；
   tasks.group_id 可空，首版不用）。
2. src-tauri/src/db.rs：rusqlite 连接管理（数据库文件放 {app_data_dir}/todoedge/todo.db，
   目录不存在则创建）；自管 migration（schema_version 表记录已应用版本）。
   连接用 Mutex<Connection> 挂在 Tauri State，全应用一个连接。
3. src-tauri/src/commands.rs 暴露 invoke 命令：
   - list_tasks() -> Vec<Task>            // 未完成在前？不——返回全部，排序由前端做，
                                           //   但 SQL 需返回 done/done_at/remind_at 等全字段
   - add_task(title, remind_at: Option<String>) -> Task
   - toggle_task(id) -> Task               // 切换 done，置 done_at
   - delete_task(id) -> ()
   - update_task(id, title?, remind_at?) -> Task   // M2 改期用，现在就留好
   - get_setting(key) / set_setting(key, value)
4. Task 结构体 derive Serialize（camelCase 字段给前端），时间字段用 RFC3339 字符串传递。
   所有时间一律存 UTC。
5. 前端 src/lib/api.ts 封装以上 invoke，类型定义与 Rust 对齐。
6. cargo check 通过 + 前端 tsc 无错误。
7. 提交："M0-3: 数据层"。
```

### 验收（你来操作）

- [x] agent 报告 cargo check 与 tsc 均无错误（本卡无界面，数据是否真的落盘在 M0-4 一起验）

### 已知坑

- rusqlite 默认 feature 即 bundled SQLite，无需系统装 SQLite。
- `app_data_dir` 在 Tauri 2 是 `app.path().app_data_dir()`，别用 v1 API。

## M0-4 基础清单界面

**前置**：M0-3
**目标**：普通窗口形态的最小可用待办：添加/勾选/删除 + 正确排序 + 重启数据还在。素 UI。

### 给 agent 的任务描述（直接粘贴）

```
实现 M0 基础界面。先读：
- D:\ztodo\docs\01-产品方案框架-v1.md 第 5.2 节（清单排序规则）
- D:\ztodo\docs\02-开发总指南.md 第 4.2 节

要求（本卡是素 UI，黑白 + 系统字体，布局对就行，不做任何视觉打磨）：
1. src/components/ 下实现：
   - 顶部输入框：回车添加任务（本卡暂不做 ⏰/＋ 按钮和自然语言，M1/M2 再加）
   - 任务列表：checkbox 勾选、hover 显示 × 删除
   - 已完成任务：显示划线样式，排底部（注意：这是 M0 临时方案，M3 会改成周报视图）
2. 排序规则（核心逻辑，按 01 文档 5.2③）：
   未完成任务单一清单：过期（remind_at 已过，按时间升序）→ 今日（remind_at 在今天，
   按时间升序）→ 未来与无日期混排（按 created_at 升序）。已完成任务排在最后。
3. 前端用 useTasks hook：加载时 list_tasks，每次操作后全量重拉刷新（数据量小，保持简单）。
4. 「今日/过期」的判定用本地时区的自然日（dayjs）。
5. npm run tauri dev 自测：添加两条任务、勾一条、删一条、重启 dev 进程确认数据还在。
6. cargo check + tsc 无错误后提交："M0-4: 基础清单界面"。
```

### 验收（你来操作）

- [x] 输入框输入文字回车，任务出现在列表
- [x] 勾选后任务划线并移到列表底部
- [x] 鼠标悬停任务行出现 ×，点击后任务消失
- [x] **关闭应用重新打开，任务都还在**（M0 最重要的验收项）
- [x] （排序可粗验）添加几条任务观察顺序符合：无日期任务按添加先后排列

### 已知坑

- dev 模式重启（Ctrl+C 再 `npm run tauri dev`）不等同于关闭应用——数据在 SQLite 文件里，两种方式都应保留。
