**阅读顺序**：你只需通读 01（已确认）和本指南第 2、7、8 节。任务卡按顺序逐张执行，不需要预习后面阶段的卡。

**每张任务卡的结构**：

- **给 agent 的任务描述**——一段完整 prompt，直接复制粘贴到终端 agent 对话框即可（已含"先读哪些文档"的指令）
- **验收清单**——你亲手操作验证的步骤，全部打勾才算完成这张卡
- **已知坑**——提前告知 agent 的技术陷阱，卡里已写入任务描述，供你了解

**核心循环（小步验证）**：

```
取下一张任务卡 → 粘给 agent → agent 实现 → 你运行验证
   ↑                                                ↓
   └──────── 有问题：描述现象给 agent 修 ←── 验收全过：让 agent 提交 git
```

## 2. 多模型协作分工

你手上的工具各有所长，分工如下：

| 工具 | 角色 | 用途 |
|---|---|---|
| **终端 agent（主力）** | 全栈工程师 | 写全部代码、跑命令、修 bug、管 git。按任务卡逐张执行 |
| **v0.dev（视觉）** | UI 设计师 | M1-1 生成面板视觉原型（它产出 React+Tailwind 代码，可复用） |
| **网页对话模型（顾问）** | 技术评委 | 仅在卡壳时用：把 agent 的报错/方案贴过去要第二意见，交叉验证后把结论带回给终端 agent |

**协作纪律**：

1. **一次只有一个终端 agent 在改代码**。换用另一家 agent 前先让它提交 git，避免改动互相覆盖。
2. 网页模型只出主意不动代码；它的建议必须由终端 agent 落地。
3. 所有 agent（无论哪家）开工前都先读 `AGENTS.md`（仓库根目录，M0-2 创建，模板见附录 A）——这是跨工具的通用约定。
4. 卡壳超过 3 轮修不好：让 agent `git revert` 回上一张卡的提交，换一家 agent 重做这张卡。**回滚不是失败，是止损。**

## 3. 技术栈与版本约定

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | Tauri **2.x**（禁用 1.x） | API 完全不同，任务卡按 v2 语法写 |
| 前端 | React 18 + TypeScript + Vite | 与 v0.dev 输出同栈，原型代码可直接搬 |
| 样式 | Tailwind CSS 4 | v0.dev 默认输出；配合 CSS 变量实现双主题双材质 |
| 数据 | rusqlite + SQLite | 不用 sqlx（编译期校验对新手有坑）；migration 自管（`schema_version` 表） |
| 透明效果 | window-vibrancy | `apply_mica()` / `apply_acrylic()` |
| 通知 | windows-rs（WinRT Toast） | M2 自写（官方插件不支持按钮），M1 先用 tauri-plugin-notification 过渡 |
| 剪贴板 | tauri-plugin-clipboard-manager | 周报一键复制 |
| 热键 | tauri-plugin-global-shortcut | M3 |
| 自启 | tauri-plugin-autostart | M3 |
| 系统调用 | windows-rs（windows crate） | Win32 窗口样式、WorkerW、全屏检测 |
| 时间 | Rust: chrono；前端: dayjs | 周报按 ISO 周（周一起始） |

**依赖新增纪律**：agent 不得自行引入上表之外的 crate / npm 包；确有必要先向你说明理由并征得同意（你只需问一句"不加行不行"）。

## 4. 系统架构

### 4.1 窗口模型：单窗口动态尺寸（核心设计）

整个应用**只有一个主窗口**，贴边形态靠动态改变窗口几何实现，不用多窗口：

```
收起态：窗口 6px 宽 × 屏高40%，贴右缘垂直居中，DOM 显示「细条视图」
展开态：窗口 340px 宽 × 屏高70%，贴右缘垂直居中，DOM 显示「面板视图」

细条视图 mouseenter(300-500ms) → invoke("expand_panel")
   → Rust: set_size + set_position（贴右缘）
   → 前端切换到面板视图
面板视图 mouseleave(1-2s，编辑态除外) → invoke("collapse_panel") → 反向
```

选单窗口而非「细条+面板」双窗口的原因：双窗口的鼠标事件接力、显示/隐藏时序都容易出诡异 bug；单窗口只是几何变化，状态机简单可靠。唯一的例外是设置小窗（M2-4）和未来的周报独立窗口，它们是普通窗口不参与贴边逻辑。

**所有窗口一律**：`decorations(false)`、`shadow(false)`、`resizable(false)`、`skip_taskbar(true)`，并通过 Win32 加 `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`（不抢焦点、不进 Alt+Tab）。Tauri 的 `focused(false)` 有已知 bug（tauri#7519），不可依赖。

### 4.2 数据流

```
前端(React) --invoke--> Rust commands --rusqlite--> SQLite(todo.db)
前端状态：自定义 hook（useTasks）本地维护，操作后全量重拉（数据量小，简单可靠）
Rust 主动推送：调度器/通知事件 --emit--> 前端监听刷新
```

- 数据库路径：`{app_data_dir}/todoedge/todo.db`
- 所有时间存 UTC（TIMESTAMP），前端用 dayjs 转本地时区显示
- 表结构见 01 文档第 6 节（tasks 含 group_id 预留字段，settings 键值表）

### 4.3 提醒调度器（Rust 常驻任务）

```
tokio::spawn 每 30s：
  SELECT * FROM tasks WHERE done=0 AND notified=0 AND remind_at <= now
  → 每条：发 Toast（携带 task_id）+ UPDATE notified=1
「稍后提醒」：remind_at += 10min，notified 重置 0（重新进入调度）
```

### 4.4 目录结构规划

```
D:\ztodo\                    ← 仓库根（git 在此初始化）
├── AGENTS.md                ← agent 通用约定（附录 A）
├── docs\                    ← 本套文档
├── src\                     ← 前端
│   ├── main.tsx / App.tsx
│   ├── components\          ← Strip(细条) Panel(面板) Overview NewTask
│   │                            TaskList TaskItem StatusBar ReportView ...
│   ├── lib\                 ← api.ts(invoke封装) parseTime.ts(自然语言)
│   └── styles\              ← theme.css（CSS 变量：light/dark × mica/solid）
└── src-tauri\               ← Rust
    ├── tauri.conf.json
    ├── migrations\          ← SQL 迁移文件（001_init.sql ...）
    └── src\
        ├── main.rs / lib.rs
        ├── db.rs            ← rusqlite 连接、migration、查询
        ├── commands.rs      ← invoke 命令层
        ├── window_ctl.rs    ← expand/collapse/Win32 样式/全屏检测

        └── toast.rs         ← WinRT Toast（M2）
```

## 7. 开发工作流细则

### 7.1 每次会话这样开始

打开终端 agent（工作目录 `D:\ztodo`），粘贴任务卡的「给 agent 的任务描述」。卡片已含读文档指令，不需要你额外解释背景。

### 7.2 验证方式（你无代码基础，全程只需这两招）

1. **跑起来看**：让 agent 执行 `npm run tauri dev`（或它已在跑就按卡片验收步骤操作界面），对照验收清单逐条打勾。
2. **描述现象**：出问题时，用"我做了 X，预期看到 Y，实际看到 Z"句式告诉 agent，附截图（agent 能看图）。禁止自己猜着改代码。

### 7.3 Git 纪律（agent 全权代管，你只下口令）

- 每张卡验收全过后，对 agent 说：**"验收通过，提交"**——它会自动 commit（不需要 push，本地仓库即可）。
- 修 bug 也是一次 commit。
- 你的两句救命口令：**"回滚到上一张卡"**（agent 执行 revert）；**"看看改了什么"**（agent 汇报 diff）。

### 7.4 出问题时的升级路径

```
描述现象 → agent 修（最多 3 轮）
  ├─ 修好 → 验收 → 提交
  └─ 3 轮未好 → 贴给网页模型要第二意见 → 结论带回终端 agent
                  └─ 仍不行 → "回滚到上一张卡" → 换一家终端 agent 重做这张卡
```

## 8. 风险与技术要点速查

按风险降序，agent 实现对应模块前应重读 01 文档对应章节：

1. **WinRT Toast 按钮**（M2-1）：官方 tauri-plugin-notification 不支持按钮，必须 windows-rs 自写 Toast XML + activation 事件路由。参考社区 tauri-plugin-windows-notifications。
2. **WorkerW pin 桌面**（M3-5）：未文档化 Shell 行为（Progman → 0x052C → WorkerW → SetParent），与 Tauri 窗口库可能有兼容坑。排在最后，失败可砍。
3. **焦点控制**（M1-2）：一律用 Win32 样式三件套硬保底（WS_EX_NOACTIVATE + WS_EX_TOOLWINDOW + SW_SHOWNOACTIVATE 语义）。
4. **Mica**（M1-3）：需窗口 `transparent: true` + CSS 背景透明；Win11 22621+ 才有 Mica；性能注意不用 blur 模式。
5. **中文自然语言时间**（M2-3）：自写规则白名单（今天/明天/后天/周X/上午下午晚上N点/N分钟后/N小时后/HH:MM），解析结果必须实时预览，失败回退纯标题。不引入大型 NLP 库。
6. **时区**：一律 UTC 存储 + dayjs 本地显示，避免"差 8 小时"经典 bug。

## 9. 未来功能：统信 UOS20 适配（本阶段不实现，仅架构纪律）

为未来 Linux/UOS 适配，**现在就要遵守**（写进 AGENTS.md，agent 会自动执行）：

- 所有 Win32/WinRT 调用（窗口样式、全屏检测、Toast、WorkerW）只允许出现在 `window_ctl.rs`、`toast.rs` 内，并用 `#[cfg(target_os = "windows")]` 门控；
- 对外暴露统一接口（trait `PlatformWindow` / `PlatformNotifier`），Linux 实现留空；
- Linux 降级路径（未来实现时）：Mica → 实体模式；WinRT Toast → org.freedesktop.Notifications；贴边逻辑复用 tao 能力；WorkerW 无对应物直接不做。

## 附录 A：AGENTS.md 模板

M0-2 任务卡会让 agent 把以下内容写入 `D:\ztodo\AGENTS.md`（可按需微调）：

```markdown
# TodoEdge 项目约定（所有 AI agent 必读）

## 这是什么
贴边常驻的极简 Windows 待办。完整需求见 docs/01-产品方案框架-v1.md（单一事实来源，
界面/行为规格以它为准，不得自行发挥）。开发流程与技术架构见 docs/02-开发总指南.md。

## 技术栈（不得擅改）
Tauri 2.x / React 18 + TS + Vite / Tailwind 4 / rusqlite / window-vibrancy /
windows-rs。新增任何依赖前必须向用户说明并获同意。

## 硬性规则
1. 单主窗口贴边架构：expand/collapse 改窗口几何，见 docs/02 第 4.1 节。
2. 所有 Win32/WinRT 调用仅限 window_ctl.rs / toast.rs，#[cfg(windows)] 门控。
3. 时间一律 UTC 存储，前端 dayjs 本地显示。
4. UI 文案全部中文；代码注释中文；变量命名英文。
5. 不实现任务卡之外的功能，不加"顺手优化"。
6. 数据库 schema 变更必须走 src-tauri/migrations/ 新增迁移文件，禁止改历史迁移。

## 常用命令

npm run tauri build # 打安装包
cargo check         # Rust 编译检查（在 src-tauri/ 下）

## 用户背景
用户无代码基础：解释用日常语言；验证只靠运行应用看效果；git 由你全权代管，

```
