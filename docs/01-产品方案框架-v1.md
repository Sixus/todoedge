# TodoEdge 产品方案框架 v1.0

> 贴边常驻的极简 Windows 待办小条。平时收成屏幕右缘一条半透明细线，鼠标停留即滑出清单，到点弹 Windows 原生通知，通知内可直接完成任务或稍后提醒。
>
> 状态：方案框架（已含三轮 grill 深化结论），待用户确认后进入开发指南编写。
> 日期：2026-08-30

---

## 1. 产品定位

- **一句话**：贴边收起为主的极简待办，鼠标一碰滑出清单，原生通知可操作。
- **目标用户**：仅开发者本人自用。
- **界面语言**：仅中文。
- **开发方式**：全程 vibe coding——终端 agent（如 ZCode）协作开发，用户小步验证。
- **核心价值**：待办始终「在场」但不打扰——收起时几乎不可见，呼出时一步直达，提醒时无需切换应用。

## 3. 窗口形态与交互规格

### 3.1 三种窗口形态

1. **收起态（默认）**：右缘竖向半透明细条。宽 4–6px，高约屏幕高度 40%，垂直居中，Mica/半透明白色，悬停时轻微增亮（参考 iOS Home Indicator 的气质）。不进任务栏、不进 Alt+Tab、不抢焦点。
2. **展开态**：从右缘向左滑出的面板。宽 320–360px，高为屏幕的 60–70%（固定，不随内容伸缩），任务超出时面板内滚动。滑出动画 150–250ms（位移 + 淡入），收回同理。
3. **Pin 桌面态（M3）**：Fences 式钉在壁纸层——窗口位于壁纸之上、桌面图标之下，Win+D 不会使其消失，作为「桌面常驻便签」用。

### 3.2 状态机

```
[收起] --鼠标悬停细条 300-500ms--> [展开]
[展开] --鼠标离开面板 1-2s--> [收起]
[展开] --点击面板外/Esc（编辑中）--> [收起]
任意态 --前台全屏应用检测--> [隐藏]（细条也隐去，退出全屏恢复）
```

- 全屏检测：Rust 侧轮询 `SHQueryUserNotificationState`（间隔约 2s，开销可忽略）。
- 「编辑中」判定：焦点在面板输入框内时，鼠标离开不自动收，改为点击外部收起，避免打字时被收走。

### 3.3 多显示器与位置记忆

- 细条/面板仅存在于主屏右缘（`primary_monitor`），其余屏幕无任何窗口。
- 停靠位置（右缘垂直居中）由代码计算，无需用户配置；用户可拖动细条调整垂直位置（简单实现：拖动记录偏移量，持久化到设置表）。

### 3.4 关键窗口实现要点（技术锚点）

- Tauri 原生：`decorations(false)` 无边框、`skip_taskbar(true)`、`shadow(false)`、`resizable(false)`。
- 不抢焦点三件套（自写 Rust，经 `window.hwnd()` 调 Win32）：扩展样式加 `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`，显示走 `SW_SHOWNOACTIVATE` 语义（Tauri `show()` + 样式兜底；Tauri `focused(false)` 有已知 bug #7519，不可依赖）。
- 悬停检测：细条窗口监听 `WM_MOUSEMOVE`（前端 mouseenter + Rust 定时器双保险），延时 300–500ms 触发展开。
- 自动收起：前端 `mouseleave` 启动 1–2s 倒计时；Rust 侧 `GetCursorPos` 轮询兜底（防止前端事件丢失）。
- Pin 桌面态（M3）：WorkerW 方案——`FindWindow("Progman")` → `SendMessageTimeout(0x052C)` 生成 WorkerW → `SetParent` 挂入。参考 3939LiveWallpaper（C# 可移植）、Lively Wallpaper、Rainmeter。注意与窗口库的兼容坑需实测，故排在最后。

## 4. 提醒系统规格

### 4.1 数据层面的提醒语义

- 每个任务至多一个提醒时间（单次，不重复）。可为空（无提醒任务）。
- 到点：弹 Windows 原生 Toast，声音用系统默认。
- 过点未完成：进入「过期」状态，排在任务清单最前、计数于概览区，**不重复弹通知**，直到用户完成/改期/清除提醒。
- 「稍后提醒」：固定间隔 10 分钟，点击后任务的提醒时间 +10min 重新进入调度。

### 4.2 Toast 通知结构

```
标题：待办提醒
正文：{任务标题}（如已过期显示「已过期 X 分钟」）
按钮：[完成]  [稍后提醒(10分钟)]
行为：点通知主体 → 呼出贴边面板并高亮该任务
     点 [完成] → 任务完成，不弹面板（不打断当前工作）
     点 [稍后提醒] → 10 分钟后重新提醒
```

- 实现路线（最大技术风险点）：Tauri 官方 `tauri-plugin-notification` **不支持按钮**，须绕过；在 Rust 侧用 `windows-rs` WinRT `ToastNotification` 自定义 Toast XML + 激活事件监听，按钮回调路由进 Tauri 事件总线驱动前端刷新。
- 提醒调度器：Rust 侧 `tokio` 定时轮询（每 30s 查一次 SQLite 中 `remind_at <= now && 未完成 && 未通知`），触发 Toast。应用未运行时不提醒（自用场景可接受，不做系统级计划任务）。

### 4.3 中文自然语言时间解析（M2）

- 输入示例：「下午3点交报告」「明天9点开会」「周五 14:30 复盘」。
- 解析结果在输入框下方实时预览（如「将提醒：今天 15:00」），回车即写入；解析失败则该部分按纯标题处理。
- 修正方式：点任务的提醒时间按钮弹出 Win11 风格 DateTimePicker 点选。
- 实现建议：优先评估 `chrono-english`/自写简单规则（今天/明天/后天/周X/上午下午晚上 X 点/X分钟后/X小时后 + HH:MM），中文场景规则有限，自写可控性高于引入大库；不准确时有点选器兜底。

## 5. 界面结构（展开态面板）

### 5.1 四段式布局

```
┌──────────────────────────────┐
│ 8月30日 星期日                │ ① 概览区：日期、星期、清单情况
│ 过期 2 · 今日 5               │
├──────────────────────────────┤
│ [新建任务…          ⏰  ＋]  │ ② 新建任务区：输入框，框内右侧提醒/添加按钮
├──────────────────────────────┤
│ □ 交报告（昨天 17:00）        │ ③ 任务清单区：单一清单，内部滚动
│ □ 开会（今天 15:00）          │    排序：过期 → 今日 → 未来+无日期
│ □ 写周报（明天 10:00）        │    未来与无日期混排，按新建时间先后
│ □ 买咖啡                     │
├──────────────────────────────┤
│ 未完成 4             ☑  ⚙   │ ④ 底栏：左状态 / 右快捷按钮（已完成、设置）
└──────────────────────────────┘
```

### 5.2 各区规格

**① 概览区**：两行。第一行日期 + 星期（如「8月30日 星期日」）；第二行清单情况「过期 n · 今日 n」，过期数 > 0 时红色高亮。纯展示。「今日」= 提醒时间在今天 0 点至 24 点之间的任务；「过期」= 提醒时间已过且未完成。

**② 新建任务区**：一行输入框，框内右侧两个按钮——提醒按钮（⏰，弹出 Win11 风格 DateTimePicker 点选）和添加按钮（＋，显式提交）；回车同样提交。自然语言解析结果在框内实时预览（如「将提醒：今天 15:00」），解析不到时间则整句按纯标题处理。

**③ 任务清单区**：全部未完成任务在**同一个清单**，不分区。排序规则：

1. 过期任务（按提醒时间升序，过期最久的在前）
2. 今日任务（按提醒时间升序）
3. 未来任务与无日期任务混排（按创建时间升序，先建的在前）

- 过期任务的时间文本红色。
- 勾选：打勾 + 划线动画（约 200ms）后滑出清单，任务按完成时间归入周报视图。
- 删除：hover 行尾出现 ×，点击即删，无确认弹窗。
- 分组能力预留：数据模型含 `group_id` 字段，首版 UI 不做任何分组。

**④ 底栏**：状态栏形式。左侧显示状态——默认「未完成 N」，存在未来提醒时改为「下一个提醒 HH:MM」。右侧两个快捷按钮：

- **已完成（☑）**：弹层覆盖主界面，进入周报视图（规格见 5.4），点返回切回主界面。
- **设置（⚙）**：弹出独立设置小窗（外观 Mica/实体、稍后提醒间隔、开机自启、细条位置重置）。

### 5.3 界面原型设计（AI 工具）

原型**要做，但放在 M0 完成后、M1 界面开工前**，范围锁定为展开态面板这一个视图：

- **工具**：v0.dev（主）——文字描述生成可交互 React 原型，与 Tauri 前端同栈，产出的组件代码可直接复用；Figma Make（辅）——生成视觉稿供对照。
- **时机理由**：M0 之前做原型，窗口形态未定，AI 会生成「普通窗口软件」的界面，必然返工；M0 完成后面板尺寸/形态已钉死（320–360px 窄高面板），此时原型目标明确、一次到位。M0 本身用素界面，不投入任何设计成本。
- **范围**：四段式面板的静态视觉，覆盖 深/浅色 × Mica 透明/实体 四组变体；顺带产出周报视图和设置小窗的视觉。
- **产出物**：确认后的截图 + v0 生成的组件代码，作为「视觉规范」附进 M1 任务卡，终端 agent 照此实现，避免视觉层面反复改。
- **原型覆盖不了的**：悬停呼出/收起动画、通知交互、贴边行为——只能在真实应用里小步验证。

### 5.4 周报视图（已完成任务的弹层）

点底栏「已完成」进入，**弹层覆盖整个面板**。选弹层而非清单区切换/独立窗口的理由：周报是停留数分钟的工作模式（翻周、浏览、复制），值得独占面板空间；同时保持单窗口架构不变（贴边窗口管理按单窗口设计）。点返回切回主界面。

```
┌──────────────────────────────┐
│ ‹  8月24日–8月30日  ›    [返回] │ ← 周导航：‹ › 翻周，默认当前周
├──────────────────────────────┤
│ 08-24  完成需求评审            │ ← 该周完成任务，按完成时间正序
│ 08-24  修复登录闪退            │    （视图内显示日期，复制时不带）
│ 08-26  发布 v1.2 版本          │
│ 08-28  整理客户反馈            │
│         （内部滚动）           │
├──────────────────────────────┤
│ [        复制周报        ]    │ ← 一键复制，复制后短暂显示「已复制 ✓」
└──────────────────────────────┘
```

- **周定义**：周一为一周起始（ISO 周），默认定位当前周，‹ › 可翻看历史周。
- **复制格式**：纯文本，仅任务列表、不带日期：

  ```
  本周完成：
  · 完成需求评审
  · 修复登录闪退
  · 发布 v1.2 版本
  ```

- **一键复制**：点「复制周报」直接写入剪贴板（tauri-plugin-clipboard-manager），无预览、无编辑环节。
- **不筛选**：复制包含该周全部完成任务（生活任务混记时，粘贴后手动删）——保持录入零摩擦，任务不分类。
- **空状态**：该周无完成任务时显示引导文案（如「本周还没有完成的任务」）。
- **升级路径**（未来，不实现）：若需要编辑长文本周报，可升级为独立窗口，架构不冲突。

## 6. 数据模型

```sql
tasks(
  id          INTEGER PRIMARY KEY,
  title       TEXT NOT NULL,
  remind_at   TIMESTAMP NULL,          -- 单次提醒时间
  notified    BOOLEAN DEFAULT 0,       -- 到点是否已弹过通知
  done        BOOLEAN DEFAULT 0,
  done_at     TIMESTAMP NULL,
  sort_order  INTEGER,                 -- 手动排序（拖拽预留，M2 可后置）
  group_id    INTEGER NULL,            -- 分组预留，首版不使用（NULL = 未分组）
  created_at  TIMESTAMP
)
settings(key TEXT PRIMARY KEY, value TEXT)  -- 外观模式、snooze 间隔、细条垂直偏移、自启
```

- 迁移用 sqlx migrate。库文件存 `%APPDATA%/todoedge/todo.db`。
- 无清单/标签/子任务/重复/归档——极简清单边界，未来要加再说。

## 7. 外观系统

- **Mica 模式（默认，Win11）**：`window-vibrancy` 的 `apply_mica()`；窗口 `transparent: true` + CSS 背景透明，内容层半透明深色/浅色跟随系统主题。仅 Win11 22621+ 启用，Win10 自动降级 acrylic 或实体。
- **实体模式（降级）**：纯色背景（深浅两套），关闭透明。用于：低配电脑、未来 UOS（Linux 无 Mica 对应物，自动走此模式）。
- 切换即时生效，无需重启。
- 前端 CSS 变量双主题（light/dark 跟随系统）× 双材质（mica/solid）= 4 组变量，实体模式是超集减法。

## 8. 性能预算

- 常驻内存目标：< 80MB（Tauri 2 + WebView2 典型值 60–70MB，可接受；若超标再优化前端）。
- CPU：空闲 0%（无高频轮询；全屏检测 2s 一次、提醒调度 30s 一次、GetCursorPos 仅在展开态生效）。
- 安装包 < 10MB；开机自启可选（默认关，注册表 Run 键或启动文件夹快捷方式）。

## 10. 风险清单（按风险降序）

1. **WinRT Toast 交互按钮**（M2）：官方插件不支持，需自写 XML + 事件路由。缓解：M1 先用无按钮通知保底可用；参考社区 tauri-plugin-windows-notifications。
2. **WorkerW pin 桌面**（M3）：未文档化 Shell 行为，与 Tauri 窗口库可能有兼容坑（DPI/消息循环）。缓解：排在最后，出问题可砍（贴边已满足 90% 需求）。
3. **中文自然语言解析**（M2）：覆盖不全。缓解：规则白名单 + 点选器兜底 + 输入框实时预览解析结果。
4. **Tauri 焦点 bug**（M1）：`focused(false)` 不可靠。缓解：Win32 样式三件套硬保底。
5. **vibe coding 本身**：无代码基础用户 + agent 协作。缓解：总指南 + 小颗粒任务卡 + 每步小验证（见开发指南，待出）。

## 11. 明确不做（边界）

- 云同步、账号体系、多端
- 清单/标签/项目/子任务/重复任务/附件
- 任务分组（仅预留 group_id 数据字段，首版无任何分组 UI）
- 番茄钟、统计报表、日历视图（周报视图是唯一例外：仅按周浏览 + 复制纯文本，无模板配置/编辑/导出文件）
- 国际化（仅中文）
- UOS 适配实现（仅写入未来文档）
- 应用未运行时的离线提醒（系统级计划任务）
