# TodoEdge 产品方案框架 v1.0

> 贴边常驻的极简 Windows 待办小条。平时收成屏幕右缘一条半透明细线，鼠标停留即滑出清单，到点弹 Windows 原生通知，通知内可直接完成任务或稍后提醒。
>
> 状态：方案框架（已含三轮 grill 深化结论），待用户确认后进入开发指南编写。
> 日期：2026-08-30

---

## 1. 产品定位

- **一句话**：贴边收起为主的极简待办，鼠标一碰滑出清单，原生通知可操作。
- **目标用户**：仅开发者本人自用。
- **界面语言**：仅中文。
- **开发方式**：全程 vibe coding——终端 agent（如 ZCode）协作开发，用户小步验证。
- **核心价值**：待办始终「在场」但不打扰——收起时几乎不可见，呼出时一步直达，提醒时无需切换应用。

## 3. 窗口形态与交互规格

### 3.1 三种窗口形态

1. **收起态（默认）**：右缘竖向半透明细条。宽 6px，高为屏幕高度 35%，垂直居中，半透明白色，悬停时轻微增亮（参考 iOS Home Indicator 的气质）。不进任务栏、不进 Alt+Tab、不抢焦点。细条高度与展开面板解绑（2026-09-05）：加最低高度只加在面板上，细条保持纤细。
2. **展开态**：从右缘向左滑出的面板。宽 340px，高 = max(屏高 35%, 500px 最低高度)，固定不随内容伸缩，任务超出时面板内滚动（弹层/清单的截断兜底见 3.2 节修订）。滑出动画 150–250ms（位移 + 淡入），收回同理。窗口模式同用此尺寸为默认与最小高度。
3. **Pin 桌面态（M3）**：Fences 式钉在壁纸层——窗口位于壁纸之上、桌面图标之下，Win+D 不会使其消失，作为「桌面常驻便签」用。

### 3.2 状态机

```
[收起] --鼠标悬停细条 滑出延时（默认 400ms，可设置）--> [展开]
[展开] --鼠标离开面板 收回延时（默认 1500ms，可设置）--> [收起]
[展开] --点击面板外/Esc（编辑中）--> [收起]（立即，不受收回延时影响）
任意态 --前台全屏应用检测--> [隐藏]（细条也隐去，退出全屏恢复）
```

- 全屏检测：Rust 侧轮询 `SHQueryUserNotificationState`（间隔约 2s，开销可忽略）。
- 「编辑中」判定：焦点在面板输入框内时，鼠标离开不自动收，改为点击外部收起，避免打字时被收走。
- 贴边时机设置（2026-09-05）：滑出/收回两个延时分开设（设置页，仅贴边模式显示），毫秒数存 settings 表，越界值钳回边界；窗口模式面板常驻，两项不显示也不生效。

### 3.3 多显示器与位置记忆

- 细条/面板仅存在于主屏右缘（`primary_monitor`），其余屏幕无任何窗口。
- 停靠位置（右缘垂直居中）由代码计算，无需用户配置；用户可拖动细条调整垂直位置（简单实现：拖动记录偏移量，持久化到设置表）。

### 3.4 关键窗口实现要点（技术锚点）

- Tauri 原生：`decorations(false)` 无边框、`skip_taskbar(true)`、`shadow(false)`、`resizable(false)`。
- 不抢焦点三件套（自写 Rust，经 `window.hwnd()` 调 Win32）：扩展样式加 `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`，显示走 `SW_SHOWNOACTIVATE` 语义（Tauri `show()` + 样式兜底；Tauri `focused(false)` 有已知 bug #7519，不可依赖）。
- 悬停检测：细条窗口监听 `WM_MOUSEMOVE`（前端 mouseenter + Rust 定时器双保险），延时 = 设置页「滑出延时」（默认 400ms）触发展开。
- 自动收起：前端 `mouseleave` 启动收回延时倒计时（默认 1.5s，可设置）；Rust 侧 `GetCursorPos` 轮询兜底（防止前端事件丢失）。
- Pin 桌面态（M3）：WorkerW 方案——`FindWindow("Progman")` → `SendMessageTimeout(0x052C)` 生成 WorkerW → `SetParent` 挂入。参考 3939LiveWallpaper（C# 可移植）、Lively Wallpaper、Rainmeter。注意与窗口库的兼容坑需实测，故排在最后。

### 3.5 系统托盘（M4，2026-09-07 新增）

- 托盘图标常驻，使用重制后的应用图标（见第 7 节），悬停提示「TodoEdge」。
- **左键单击 = 切换面板**：贴边模式下与点细条等效（收起→展开、展开→收起，细条被其他窗口挡住时的保险入口）；窗口模式下切换主窗口显示/隐藏。
- **右键菜单三项**：展开/收起面板、打开设置、退出。
  - 「打开设置」：贴边模式下先展开面板再打开设置弹层；窗口模式直接打开设置。
  - 「退出」：彻底退出进程（提醒调度随之中止）；设置页原有的「退出应用」按钮保留，两处等效。
- 实现：Tauri 2 内置 tray 能力（`tauri` 依赖开启 `tray-icon` feature，官方内置，不引入第三方库）；托盘事件路由进现有 Tauri 事件总线，不直接碰 Win32。

## 4. 提醒系统规格

### 4.1 数据层面的提醒语义

- 每个任务至多一个提醒时间（单次）。可为空（无提醒任务）。可叠加重复规则，重复语义见 4.4（2026-09-07 修订：原「单次，不重复」，重复已解禁）。
- 到点：弹 Windows 原生 Toast，声音用系统默认。
- 过点未完成：进入「过期」状态，排在任务清单最前、计数于概览区，**不重复弹通知**，直到用户完成/改期/清除提醒。新建/改期时提醒时刻已是过去（生来过期）同样直接进过期态、不弹（2026-09-01 修订）。
- 「稍后提醒」：固定间隔 10 分钟，点击后提醒时间改为**当前时间 + 间隔**重新进入调度（2026-09-01 修订：原「自原提醒时间 +10min」对过期补弹通知会得到仍在过去的时刻，导致立即重弹死循环）。

### 4.2 Toast 通知结构

```
标题：待办提醒
正文：{任务标题}（如已过期显示「已过期 X 分钟」）
按钮：[完成]  [稍后提醒(10分钟)]
行为：点通知主体 → 呼出贴边面板并高亮该任务
     点 [完成] → 任务完成，不弹面板（不打断当前工作）
     点 [稍后提醒] → 10 分钟后重新提醒
```

- 实现路线（最大技术风险点）：Tauri 官方 `tauri-plugin-notification` **不支持按钮**，须绕过；在 Rust 侧用 `windows-rs` WinRT `ToastNotification` 自定义 Toast XML + 激活事件监听，按钮回调路由进 Tauri 事件总线驱动前端刷新。
- 提醒调度器：Rust 侧 `tokio` 定时轮询（每 30s 查一次 SQLite 中 `remind_at <= now && 未完成 && 未通知`），触发 Toast。应用未运行时不提醒（自用场景可接受，不做系统级计划任务）。

### 4.3 中文自然语言时间解析（M2）

- 输入示例：「下午3点交报告」「明天9点开会」「周五 14:30 复盘」。
- 解析结果在输入框下方实时预览（如「将提醒：今天 15:00」），回车即写入；解析失败则该部分按纯标题处理。
- 修正方式：点任务的提醒时间按钮弹出 Win11 风格 DateTimePicker 点选。
- 实现建议：优先评估 `chrono-english`/自写简单规则（今天/明天/后天/周X/上午下午晚上 X 点/X分钟后/X小时后 + HH:MM），中文场景规则有限，自写可控性高于引入大库；不准确时有点选器兜底。

### 4.4 任务重复（M4，2026-09-07 新增；同日修订：滚动式单卡方案废弃，改为「结算旧卡 + 新建下一期」的实例化模型，并去掉每年档）

- **档位**：不重复（默认）/ 每天 / 每周 / 每月，不做自定义周期与星期几组合。
- **入口**：提醒设置弹层（ReminderPicker）内、时间行下方「重复」行，**常驻显示**（2026-09-08 修订：原「未设提醒时间的任务不显示」入口太深；弹层的确定必然携带时间，可顺手选重复）。清除提醒时重复一并重置为「不重复」。
- **实例化语义**：勾选完成 = 结算旧卡 + 新建下一期新卡。
  - 结算：旧卡照常进完成态，收进「今日已完成」分组，写一条完成记录（completions 表）计入周报；完成/撤销提示与普通任务完全一致。
  - 新卡：同标题同规则**另建一条任务**，提醒时间推进到下一期，notified 归零等下期再弹；按全新任务入库（排序按创建时间排在未来区最后），离场/入场动画与普通增删一致。新卡以 origin_id 指回被结算的旧卡。
- **勾回（撤销）**：旧卡勾回 = 清完成态 + 删对应完成记录 + 删该次完成生成的新卡；新卡已被再结算时保留不删（不丢数据）。
- **过期未完成**：与单次任务完全一致——挂过期区（清单最前、计入概览计数、不重弹通知），勾掉才结算+出新卡。新卡提醒时间 = 从过期那期起按周期推进，**直到落到第一个未来时刻**（过期多日只补一期，跳过中间错过的期数，不堆积）。
- **周期推进规则**：保持原钟点不变；每天 +24h、每周 +7d、每月 +1 自然月（月末钳位：1月31日→2月28日）。内部按 UTC 计算。
- **与提醒联动**：改期（点选新时间）保留重复规则，锚点变为新时间。Toast 的 [完成] 按钮与 toggle_task 走同一条完成路径（结算+出新卡同样生效）。
- **完成记录与周报**：周报（5.4 节）数据源从 `tasks.done` 改为独立的 completions 完成记录表。所有完成（重复/非重复）统一写记录；周报里删除一行 = 只删该条记录，任务本体不动，可撤销（原样插回）。存量已完成任务由迁移脚本回填进记录表，周报历史不丢。
- **清单标记**：设置了重复的任务在时间旁显示循环标记（↻），一眼区分。

## 5. 界面结构（展开态面板）

### 5.1 四段式布局

```
┌──────────────────────────────┐
│ 8月30日 星期日                │ ① 概览区：日期、星期、清单情况
│ 过期 2 · 今日 5               │
├──────────────────────────────┤
│ [新建任务…          ⏰  ＋]  │ ② 新建任务区：输入框，框内右侧提醒/添加按钮
├──────────────────────────────┤
│ □ 交报告（昨天 17:00）        │ ③ 任务清单区：单一清单，内部滚动
│ □ 开会（今天 15:00）          │    排序：过期 → 今日 → 未来+无日期
│ □ 写周报（明天 10:00）        │    未来与无日期混排，按新建时间先后
│ □ 买咖啡                     │
├──────────────────────────────┤
│ 未完成 4             ☑  ⚙   │ ④ 底栏：左状态 / 右快捷按钮（已完成、设置）
└──────────────────────────────┘
```

### 5.2 各区规格

**① 概览区**：两行。第一行日期 + 星期（如「8月30日 星期日」）；第二行清单情况「过期 n · 今日 n」，过期数 &gt; 0 时红色高亮。纯展示。「今日」= 提醒时间在今天 0 点至 24 点之间的任务；「过期」= 提醒时间已过且未完成。

**② 新建任务区**：一行输入框，框内右侧两个按钮——提醒按钮（⏰，弹出 Win11 风格 DateTimePicker 点选）和添加按钮（＋，显式提交）；回车同样提交。自然语言解析结果在框内实时预览（如「将提醒：今天 15:00」），解析不到时间则整句按纯标题处理。

**③ 任务清单区**：全部未完成任务在**同一个清单**，不分区。排序规则：

1. 过期任务（按提醒时间升序，过期最久的在前）
2. 今日任务（按提醒时间升序）
3. 未来任务与无日期任务混排（按创建时间升序，先建的在前）

- 过期任务的时间文本红色。
- 勾选：打勾 + 删除线从左到右扫过标题（约 180ms），随后行渐隐、高度收拢（共约 460ms），下方元素平滑上移，归入清单尾部的「今日已完成」分组（见下）；更早完成的只在周报视图看。
- 删除：hover 行尾出现 ×，点击即删，无确认弹窗。
- 新增任务：新行在清单中自 0 高度展开 + 淡入（约 200ms），下方元素随之平滑下移。
- 弹层（提醒选择/编辑）：从锚点方向缩放淡入（约 150ms）；点卡片外关闭为瞬时，无退场动画。
- **撤销 toast**：勾选完成或删除任务后，面板底部浮出提示条「已完成/已删除「任务名」+ 撤销按钮」，占满面板宽度、文字靠左、撤销按钮靠右。多条提示在底部堆叠、新触发的在旧的上方，各自独立倒计时，15 秒后自动消失，消失后不可撤销；点某条的「撤销」立即恢复该条对应的操作——完成的回到未完成清单，删除的按删除前快照原样恢复（含原排序位置）。撤销仅覆盖「完成」和「删除」，新增/编辑不提供。
- **「今日已完成」分组（M4）**：清单尾部固定分组，收纳今天勾选完成的任务，按完成时间倒序（最近完成的在上）。默认缩起，标题行显示「⌄ 今日已完成 n」，点击展开/缩起；展开状态不持久化，面板收起再展开、跨天都回到默认缩起。分组内的行仍可勾选打回、编辑、删除，但不参与拖拽排序。首版不提供自建分组（数据模型 `group_id` 仍预留不用，分组为纯展示层概念）。
- **全局动画开关（feature/animations）**：设置里的「动画」开关为总开关，控制面板滑出/缩进（Rust 侧窗口动画）、勾选完成离场、新增任务入场、分组展开/收起、撤销提示弹出/渐隐、提醒/编辑弹层弹出；关闭时上述动画一律瞬时完成，其余交互不变。

**④ 底栏**：状态栏形式。左侧显示状态——默认「未完成 N」，存在未来提醒时改为「下一个提醒 HH:MM」。右侧两个快捷按钮：

- **已完成（☑）**：弹层覆盖主界面，进入周报视图（规格见 5.4），点返回切回主界面。
- **设置（⚙）**：弹出独立设置小窗（外观 透明/实体、稍后提醒间隔、动画总开关、开机自启、细条位置重置）。

### 5.3 界面原型设计（AI 工具）

原型**要做，但放在 M0 完成后、M1 界面开工前**，范围锁定为展开态面板这一个视图：

- **工具**：v0.dev（主）——文字描述生成可交互 React 原型，与 Tauri 前端同栈，产出的组件代码可直接复用；Figma Make（辅）——生成视觉稿供对照。
- **时机理由**：M0 之前做原型，窗口形态未定，AI 会生成「普通窗口软件」的界面，必然返工；M0 完成后面板尺寸/形态已钉死（320–360px 窄高面板），此时原型目标明确、一次到位。M0 本身用素界面，不投入任何设计成本。
- **范围**：四段式面板的静态视觉，覆盖 深/浅色 × 透明/实体 四组变体；顺带产出周报视图和设置小窗的视觉。
- **产出物**：确认后的截图 + v0 生成的组件代码，作为「视觉规范」附进 M1 任务卡，终端 agent 照此实现，避免视觉层面反复改。
- **原型覆盖不了的**：悬停呼出/收起动画、通知交互、贴边行为——只能在真实应用里小步验证。

### 5.4 周报视图（已完成任务的弹层）

点底栏「已完成」进入，**弹层覆盖整个面板**。选弹层而非清单区切换/独立窗口的理由：周报是停留数分钟的工作模式（翻周、浏览、复制），值得独占面板空间；同时保持单窗口架构不变（贴边窗口管理按单窗口设计）。点返回切回主界面。

```
┌──────────────────────────────┐
│ ‹  8月24日–8月30日  ›    [返回] │ ← 周导航：‹ › 翻周，默认当前周
├──────────────────────────────┤
│ 08-24  完成需求评审            │ ← 该周完成任务，按完成时间正序
│ 08-24  修复登录闪退            │    （视图内显示日期，复制时不带）
│ 08-26  发布 v1.2 版本          │
│ 08-28  整理客户反馈            │
│         （内部滚动）           │
├──────────────────────────────┤
│ [        复制周报        ]    │ ← 一键复制，复制后短暂显示「已复制 ✓」
└──────────────────────────────┘
```

- **周定义**：周一为一周起始（ISO 周），默认定位当前周，‹ › 可翻看历史周。
- **复制格式**：纯文本，仅任务列表、不带日期：
  ```
  本周完成：
  · 完成需求评审
  · 修复登录闪退
  · 发布 v1.2 版本
  ```
- **一键复制**：点「复制周报」直接写入剪贴板（tauri-plugin-clipboard-manager），无预览、无编辑环节。
- **不筛选**：复制包含该周全部完成任务（生活任务混记时，粘贴后手动删）——保持录入零摩擦，任务不分类。
- **空状态**：该周无完成任务时显示引导文案（如「本周还没有完成的任务」）。
- **升级路径**（未来，不实现）：若需要编辑长文本周报，可升级为独立窗口，架构不冲突。

## 6. 数据模型

```sql
tasks(
  id          INTEGER PRIMARY KEY,
  title       TEXT NOT NULL,
  remind_at   TIMESTAMP NULL,          -- 单次提醒时间（重复任务为当前期时刻）
  repeat      TEXT NOT NULL DEFAULT 'none',  -- 重复规则 none|daily|weekly|monthly（M4）
  notified    BOOLEAN DEFAULT 0,       -- 到点是否已弹过通知
  done        BOOLEAN DEFAULT 0,
  done_at     TIMESTAMP NULL,
  sort_order  INTEGER,                 -- 手动排序（拖拽预留，M2 可后置）
  group_id    INTEGER NULL,            -- 分组预留，首版不使用（NULL = 未分组）
  created_at  INTEGER,
  origin_id   INTEGER NULL             -- 重复任务勾掉后新建的下一期卡指回被结算的旧卡（M4）
)
completions(                            -- 完成记录（M4）：周报数据源，重复任务每期一条
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id     INTEGER NOT NULL,
  title       TEXT NOT NULL,           -- 冗余存标题快照（任务后续改名不影响历史记录）
  done_at     TIMESTAMP NOT NULL
)
settings(key TEXT PRIMARY KEY, value TEXT)  -- 外观模式、snooze 间隔、细条垂直偏移、自启
```

- 迁移用 sqlx migrate。库文件存 `%APPDATA%/todoedge/todo.db`。
- 无清单/标签/子任务/归档——极简清单边界，未来要加再说（重复任务已于 M4 解禁，规格见 4.4；迁移 002 建 completions 表并把存量 done=1 任务回填进去）。

## 7. 外观系统

- **透明模式（默认）**：窗口 `transparent: true` 的原生逐像素透明，面板/内容层用半透明深浅色 CSS（跟随系统主题，浅约 50%、深约 45%，打磨期可微调），真实透出桌面壁纸与后方窗口；收起细条为半透明白色。
- **实体模式（可选/降级）**：不透明纯色背景（深浅两套）。用于低配电脑、杂乱桌面下提升可读性、未来 UOS。
- **为什么不用 Mica/Acrylic**（2026-08-31 修订）：窗口带 `WS_EX_NOACTIVATE` 永不激活（不抢焦点是硬需求），而 DWM 系统材质——Mica/Acrylic backdrop、`SetWindowCompositionAttribute` 的亚克力与模糊 accent——在未激活窗口上经像素采样实测都只渲染纯色兜底、无真实模糊。半透明因此由原生透明 + CSS 实现；代价是没有毛玻璃式模糊，杂乱桌面下可读性不足时调高面板不透明度或切实体。
- 切换即时生效：前端改 `data-material`（glass/solid）换 CSS 变量组即可，无 Rust 侧材质调用，无需重启。
- 前端 CSS 变量双主题（light/dark 跟随系统）× 双材质（glass/solid）= 4 组变量。
- 应用图标（M4，2026-09-07 新增）：Win11 Fluent 风圆角方形 + 白色对勾主图形 + 柔和渐变底（蓝青/绿青/紫蓝三配色在 Figma AI 对比后定稿）。生成提示词与替换流程见 docs/07 任务卡 M4-2；系统托盘图标同源（小尺寸辨识不足时再出单色简化版）。

## 8. 性能预算

- 常驻内存目标：&lt; 80MB（Tauri 2 + WebView2 典型值 60–70MB，可接受；若超标再优化前端）。
- CPU：空闲 0%（无高频轮询；全屏检测 2s 一次、提醒调度 30s 一次、GetCursorPos 仅在展开态生效）。
- 安装包 &lt; 10MB；开机自启可选（默认关，注册表 Run 键或启动文件夹快捷方式）。

## 10. 风险清单（按风险降序）

1. **WinRT Toast 交互按钮**（M2）：官方插件不支持，需自写 XML + 事件路由。缓解：M1 先用无按钮通知保底可用；参考社区 tauri-plugin-windows-notifications。
2. **WorkerW pin 桌面**（M3）：未文档化 Shell 行为，与 Tauri 窗口库可能有兼容坑（DPI/消息循环）。缓解：排在最后，出问题可砍（贴边已满足 90% 需求）。
3. **中文自然语言解析**（M2）：覆盖不全。缓解：规则白名单 + 点选器兜底 + 输入框实时预览解析结果。
4. **Tauri 焦点 bug**（M1）：`focused(false)` 不可靠。缓解：Win32 样式三件套硬保底。
5. **vibe coding 本身**：无代码基础用户 + agent 协作。缓解：总指南 + 小颗粒任务卡 + 每步小验证（见开发指南，待出）。

## 11. 明确不做（边界）

- 云同步、账号体系、多端
- 清单/标签/项目/子任务/附件（重复任务已于 M4 解禁，见 4.4）
- 任务分组（自建分组不做；仅提供固定的「今日已完成」分组，见 5.2；group\_id 字段继续预留）
- 番茄钟、统计报表、日历视图（周报视图是唯一例外：仅按周浏览 + 复制纯文本，无模板配置/编辑/导出文件）
- 国际化（仅中文）
- UOS 适配实现（仅写入未来文档）
- 应用未运行时的离线提醒（系统级计划任务）
